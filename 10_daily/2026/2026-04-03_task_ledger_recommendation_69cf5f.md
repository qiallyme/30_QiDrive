## My recommendation

### Right now
Set up a **shared Google Sheet called `Mom Task Ledger`**.

Use these columns:

- `Date Added`
- `Task`
- `Context / What she meant`
- `Category`
- `Priority`
- `Owner`
- `Due`
- `Status`
- `Source Message`
- `Notes`

Use dropdowns for:

- **Category:** meds, errands, bills, home, appointments, follow-up, check on, random
- **Priority:** urgent, this week, later
- **Owner:** Cody, Mom, Both
- **Status:** inbox, next, waiting, done, dropped

## The clean workflow

### 1. One intake place
When she sends 20 scattered texts, you dump each one into the sheet as a row.

### 2. One rule
Anything not in the ledger is **not a real task yet**.

### 3. One triage view
Filter to:
- `Status = inbox`
- sort by `Priority`, then `Due`

### 4. One execution view
Filter to:
- `Owner = Cody`
- `Status = next` or `waiting`

That keeps the chaos from becoming your brain’s job.

## When Notion becomes the better choice

Move this into Notion **only if** you need one of these:

- linked docs, notes, meds, appointments, household info all in one place
- multiple views for the same tasks
- a broader home hub system
- light documentation around each task

That’s a **phase 2** move, not the first move. Starting in Notion when the issue is already overwhelm is how you accidentally build a system instead of solving the problem. Notion is powerful, but that’s exactly why it can become friction. citeturn216741search0turn216741search20

## Best stack for you two

**Use both, but for different jobs:**

- **Google Sheet = shared task ledger**
- **Notion = home hub / reference space**

So:
- tasks live in Sheet
- stable info lives in Notion

That split is cleaner than forcing Notion to be both inbox and archive.
